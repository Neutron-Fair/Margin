# 安卓端重新规划（v0）

> 依据：`mobile-ui-design` 技能（第 0 步五问 → 平台分流 → 结构 → 视觉 → 情感 → 动效 → 原生红线 → 交付门禁），叠加已确认的「纸感规格书」设计系统。
> 交付物：本文件 + `docs/v0/android-v0.html`（源码）+ `docs/v0/*.png`（从源码渲染的截图）。
> 所有金额来自项目引擎真实输出（1000 本 / 利润 15% / 税 13% / 运费 120），不是示意数字。
> **状态：v0 设计已落到 `src/`（2026-11-20）。** 设计稿与截图保留在 `docs/v0/` 作为过程记录；实现记录见第 9 节，验证见第 10 节。

## 0. 这一轮改了什么

原来手机上跑的是「桌面双栏的缩小版」：顶部 6 个操作按钮换行、单据 4 个输入框占掉 1.5 屏、结果在右栏而手机只有一个底部 Tab 能切过去。核心动作（改一个参数 → 立刻看单本价变没变）在手机上被打断了。

这轮把信息架构推倒重排：**单栏 + 常驻价格条 + 4 个顶级 Tab**，让「价格永远在视野里」，参数就地展开。

## 2. 平台分流：Android 为主，与桌面端分化

跨平台纪律是「业务统一、表现分化」。这次的分化边界：

| 维度 | 桌面 Windows | Android |
|---|---|---|
| 布局 | 双栏：左参数 + 右结果常驻 | 单栏滚动 + 吸底价格条 |
| 单据信息 | 顶部 4 个字段常显 | 一行摘要（单号·客户·日期），点开 sheet 编辑 |
| 结果 | 右栏完整结果面板 | 价格条 2 个数字 + 「明细」页完整拆解 |
| 操作入口 | 顶部 6 个按钮 | 4 个 Tab + 右上角 ⋮ 溢出菜单 |
| 标题字族 | 宋体（Songti/SimSun） | 无衬线；**宋体只出现在报价单那张"纸"上** |
| 圆角 | 0（零圆角纪律） | 2 / 8 / pill 三分（见 6.4） |
| 动效 | 无 | 弹簧，可打断；尊重减弱动效 |
| 返回 | 关闭按钮 | 系统返回键 / 预测性返回 |

**统一（UNIFY）**：计算引擎、校验规则、存储结构、A4 导出、模块编号 01–08、术语（备损 / 拼版 / 印次 / 成本加成）、运费单列口径。

**为什么标题字族要分化**：宋体在 Windows 大字号下有"单据"气质，但 Android 系统宋体（Noto Serif CJK）笔画细、渲染发虚，17sp 标题会糊。所以把宋体保留在它真正重要的地方——**报价单那张纸**（用户最终看到的成品），App 界面本身用无衬线保证可读。

## 3. 为什么这么改（三个既有问题的根因）

| 现象 | 根因 | 改法 |
|---|---|---|
| 顶部 6 个按钮换行、挤掉首屏 | 把「一次性动作（预设/识图/AI/设置/重置）」和「目的地（明细/报价单）」平铺在同一层 | 目的地进 Tab，一次性动作进 ⋮ 与「更多」页，按「录入 / 存档 / 工具 / 危险」分组 |
| 单据 4 个输入框占 1.5 屏 | 把「每次都要填的」和「偶尔才改的」同等对待 | 默认折叠成一行摘要；实际高频只改单号和客户，日期有默认值、备注常空 |
| 结果在右栏，手机上切走就看不到 | 直接照搬桌面双栏 | 吸底价格条常驻：单本含税（大字）+ 总报价，点它进明细 |

一条补充判断：**手机上不该出现"结果页"作为独立目的地**。报价员的动作循环是「改 → 看 → 再改」，把结果放成需要跳转的页面，等于每次改动都要付一次导航成本。所以「明细」Tab 是"看构成"（一屏拆解 12 行），而"看总价"这件事由价格条零成本提供。

## 4. 新架构

```
┌─ 状态栏 ─────────────────────┐
├─ AppBar 品牌 · 单据摘要行 · ⋮ ─┤   ← 56 + 48，文档信息收成一行
├─ 订单区（数量 + 三指标 + 运费）─┤
├─ 01 内页  1.6916 /本      ⌄  ─┤   ← 折叠卡：露出金额，点开就地展开
├─ 02 衬纸  0.0828 /本      ⌄  ─┤
│   … 08 利润与税               │
├─ 价格条 单本含税 / 总报价 ─────┤   ← 常驻，朱砂只用于异常态
└─ Tab  算价 · 明细 · 报价单 · 更多 ┘
```

固定占用 184dp（AppBar 56 + 摘要 48 + 价格条 64 + Tab 56 + 安全区），滚动区约 660dp（390×844 机型）。

## 6. 设计系统（移动端增量）

纸感规格书的地/面/墨/朱砂、编号系统、零阴影纪律全部保留。以下是**为移动端新增或修正**的部分。

### 6.1 色彩

| 令牌 | 值 | 用途 | 对比度实测 |
|---|---|---|---|
| `--paper` | `#F4F2EC` | surface 纸地 | — |
| `--card` | `#FBFAF6` | 卡片 / 纸面 | — |
| `--sunken` | `#EDEAE1` | 输入框底、次级容器 | — |
| `--sunken2` | `#E4E0D5` | 条形轨道、分段控件槽 | — |
| `--ink` | `#2A2A28` | 主文字 | **12.8:1** on 纸地 |
| `--ink2` | `#6E6D68` | 次文字 | **4.63:1** on 纸地 |
| `--hair` | `#D9D6CD` | 1px 发丝线 | — |
| `--accent` | `#C7322E` | 朱砂：激活指示 / 错误 / 主 CTA | **4.78:1** on 纸地；白字其上 **5.35:1** |

**修正**：原次墨 `#7C7B76` 对纸地只有 **3.76:1**，不达移动端正文 4.5:1 线。加深到 `#6E6D68` 后 4.63:1。桌面端可维持原值（大字号场景），移动端必须用新值。

强调色只出现在：Tab 激活线、错误态、主 CTA（导出）。全部条形、chip、卡片一律走墨色与纸色差——朱砂稀缺才有信息量。初版把三个结果 chip 做成粉底，已改回纸深底（违反 60/30/10 的 10% 预算）。

### 6.2 字号：4 档

| 档 | 值 | 用途 |
|---|---|---|
| 小 | 12sp | 标签、单位、脚注、编号 |
| 正文 | 14sp | 字段值、列表正文 |
| 标题 | 17sp | 屏幕标题、卡片标题 |
| 数字 | 30sp | 单本价、成本 hero（`tabular-nums` + 负字距 −0.025em） |

字重 3 档：400 / 500 / 600。中文标签字距 0.06–0.08em（初版 0.14em 会把「材料与印刷」拆成一个个字，已修）。

唯一豁免：报价单纸面里的 7px 字号——那是 A4 缩略图，属于"纸"的像素内容，不是 UI 字号。

### 6.3 间距与触控

8 点网格：4 / 8 / 12 / 16 / 24 / 32。页边距 16。卡片内边距 14–16（高密度工具，不是消费类，不取 24–32）。

触控全部 ≥ 48dp：模块行 56、更多行 52、按钮 48、Tab 56、图标按钮 48、步进按钮 48、单据行 48。

### 6.4 形状：三分法（这是与 M3 的关键取舍）

纸感是零圆角，M3 Expressive 要求"形状多样性、绝不能全圆角矩形"。两者对冲，解法是**按元素语义分配形状**：

| 形状 | 半径 | 用在哪里 |
|---|---|---|
| 直角 | 2px | 单据容器：订单卡、模块卡、汇总卡、报价单纸面 |
| 控件圆角 | 8px | 所有可操作物：输入框、按钮、步进器、字段格 |
| 胶囊 | pill | 状态标签、chip、分段控件槽、Tab 激活指示 |

这样"纸"永远是直的，"手上的东西"是圆的——形状本身就在表达"这是数据 / 这是能按的"。同时满足 M3 的形状对比要求，且不破坏纸感。

### 6.5 动效

- 位置与尺寸用弹簧曲线（CSS `linear()` 拟合 damping≈0.6 的 spatial spring），颜色与透明度用临界阻尼（`cubic-bezier(.2,0,0,1)`）。**不使用固定 `transition: 300ms linear`**。
- 模块展开/收起、Tab 切换、价格条展开走 spatial；数字变化的高亮淡入淡出走 effects。
- `prefers-reduced-motion: reduce` 时全部退化为无动画（Android 侧对应 `ANIMATOR_DURATION_SCALE == 0`）。
- 数字改动时不做计数滚动动画——这是核算工具，滚动中的数字会被误读。

### 6.6 与 M3 Expressive 的取舍

**采纳**：弹簧动效（不用 tween）、48dp 触控、edge-to-edge 与 WindowInsets、系统返回关闭面板而非关应用、surface 层级用底色差表达（纸地/纸面/纸深/纸更深 4 级）、关键处用强调字重、FAB 若出现则用圆角方形。

**不采纳（有理由）**：

| M3 条目 | 不采纳的理由 |
|---|---|
| 动态取色（Material You） | 成本单要靠颜色稳定来核对。两次报价的界面颜色不同，会让"朱砂 = 异常"这条语义失效 |
| 48 个 color role 全用 | 单墨色 + 单强调色是产品识别；48 色会把它变成通用 Android 演示 |
| 35 种形状与形状形变 | 与"这是一张纸"的核心隐喻冲突。改为 3 种固定形状的语义分配（见 6.4），保留对比但不做形变 |
| 圆形/波浪进度指示器 | 导出与 OCR 的等待很短，线性细进度条更准确、不抢注意 |

判断标准一条：**凡是让界面"更活泼"但与"可核对、稳定、克制"冲突的，一律让位**；凡改善手感与可达性的，全盘接受。

## 9. 实现记录

桌面端零视觉变化：所有新规则都在 `@media (max-width: 900px)` 内。

| 文件 | 改动 |
|---|---|
| `src/ui/MobileDock.tsx` | 重写：价格条改无衬线 30sp、4 个 Tab 带图标、朱砂激活线；`active` 由当前面板推导 |
| `src/App.tsx` | 新增页头 `⋮`（`.header-menu`）、单据摘要行（`.doc-summary`）与 `docExpanded`；模块默认全折叠；给 `ToolsPanel` 传 `onReset` |
| `src/ui/panels/ToolsPanel.tsx` | 重写：录入 / 存档 / 工具 / 危险 四组，末尾「恢复默认参数」带二次确认 |
| `src/ui/panels/ResultDetailPanel.tsx` | 内联 `fontSize:38` 改成 `result-amount-sm` 类，让手机端能覆盖字号与字族 |
| `src/styles/app.css` | 手机段：页头只留 `⋮`、单据折叠、订单区三列、模块卡片化、字段 48dp + 8dp 圆角、价格条与 Tab 重排、菜单分组紧凑、明细去掉点线、大数字改无衬线 |

新增 `tools/shot-cdp.mjs`：用 CDP 精确控制视口截图（`--w/--h/--dpr`、`--eval`、`--measure`）。
**它解决了一个真实陷阱**：headless 下 `--window-size` 会被 `--force-device-scale-factor` 影响（传 390 实际得到 195 CSS 视口），直接拿它截图会把"布局溢出"误判成设计问题——第一次截出来右侧被裁就是这个原因，而 CDP 测得的 `scrollWidth == clientWidth == 390` 才是真相。
