## 本次内容

### 修复：Windows 上装不上新版本

1.1.0 / 1.1.1 的安装包在已有旧版本上**覆盖安装会失败**：安装器一闪而过（退出码 2），装完版本号没变、文件时间戳也没变，等于什么都没发生。只有先卸载再装才行。

- **根因**：安装器升级时会复制并执行旧版自带的卸载器，而旧卸载器要把整个安装目录改名成 `old-install`，这一步在本机必然失败（改名后 Abort）。旧卸载器返回非 0 → 安装器重试 5 次 → 放弃。所以问题不在「程序没关掉」，杀干净进程、等 6 秒再装一样失败。
- **修法**：安装器在初始化时先结束残留实例，再让旧卸载器「不存在」（后续找不到就直接跳过那段有缺陷的卸载流程），从而按全新安装的路径覆盖。新版装好后会写入带补丁的新卸载器，以后的升级都正常。
- **验证**：1.1.1 → 1.2.0 覆盖安装退出码 0、版本号与文件时间戳都更新；1.2.0 → 1.2.0 再覆盖同样退出码 0。

### 新增：自动检查更新（两端）

- **桌面**：「更多 → 检查更新」→ 查 GitHub Release → 有新版本就显示版本号、包大小、更新说明 → 点「下载并安装」，带进度条，装完自动是新版。
  安装流程走「先退出 → 静默卸载 → 清目录 → 静默安装」，绕开升级路径，**草稿与方案不会丢**（数据在用户目录，卸载不删）。
- **手机**：同样检查，有新版本时一键打开下载页，下载后点开安装。
- **更新源可改**，默认 `Neutron-Fair/Margin`。仓库公开时匿名即可检查更新；换回私有仓库时在面板里填一个只读 GitHub Token 即可，Token 存系统安全存储（Windows safeStorage / Android Keystore），不写普通设置、不进备份。

> 仓库为公开仓库，因此默认无需填写 Token；代码对私有与公开两种情况都支持。
