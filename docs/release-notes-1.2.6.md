## 本次内容

两个都会让报价「看起来算错」的问题，都是输入处理，不是算法。

### 修复：把一个输入删空后，报价会卡住（甚至改回来也不恢复）

现象：把任意一个数字删掉（输入框留空），整页变成「输入无效，已暂停报价」；再把数字填回去，**还是暂停**，必须去点提示里那个「已核对数值」按钮才恢复。很多时候人根本没注意到那个按钮，就以为「这个软件删个东西就废了」。

原因：空输入被当成「非法输入」记进了阻断名单，而「曾经非法 → 又变有效」会额外点亮一条「已回退，请核对」的提示，这条提示只能手点确认，不会自动消失。

修复：**清空视为「正在重输」的中间态**——不提交新值，也不阻断计算，继续用上一个有效值算下去，失焦时把显示归位。只有真正非法的输入（字母、负数、超范围）才暂停报价。

### 修复：把「每本张数」改成 0，那笔钱还在

现象：不要衬纸 / 不要灰板时，把「每本张数」改成 0，报价只掉了一点点，甚至几乎没变。

原因：以前只把「纸张」按 0 算，而**上机费和备损印张照旧计入**——衬纸清零后每本仍收 ¥0.0612（上机 ¥60 + 备损 100 张），内页清零后仍收 ¥0.0848。

修复：**每本张数为 0 = 这个部件不存在**，纸、上机费、备损印张、后工艺（覆膜/烫金/UV）全部不计。实测衬纸清零后单本从 ¥3.6650 降到 ¥3.5800，总价 ¥3,579.96（与原始算例一致）；封面清零时覆膜也一起消失。

> 注意：**内页**张数改成 0 仍会提示「必须核对」——整单没有内页属于录错，不是正常操作。

### 关于「手机版比电脑贵一半」

查证结论：**两端跑的是同一份代码**。

- 把 APK 里打包的网页资源解出来，与电脑版的构建产物逐文件比对 SHA-256，**5 个文件全部一致**（`index.html`、`app.js`、`app.css` 等）
- 计价引擎（`calc.ts` / `defaults.ts`）从 1.0.0 首发至今**一次都没改过**
- 同一组参数下两端算出的数完全一样（默认参数都是单本 ¥3.6650）

所以差异来自**参数或口径**，最常见的是这几个（1000 本默认参数的倍数）：

| 参数 | 单本 | 相对默认 |
| --- | --- | --- |
| 默认（1000 本） | ¥3.6650 | 1.00× |
| 订单 800 本 | ¥3.8871 | 1.06× |
| 订单 500 本 | ¥4.5533 | 1.24× |
| **订单 300 本** | **¥5.7377** | **1.57×** |
| 内页张数 160 | ¥5.3169 | 1.45× |
| 内页拼版 1 | ¥5.1454 | 1.40× |
| 另加 10% 利润 + 13% 税 | ¥4.5080 | 1.23× |

「贵一半多」最接近**订单数量不同**（比如手机上是 300 本、电脑上 1000 本 → 1.57 倍），其次是内页张数/拼版数。

另外注意两个不同口径：手机底部价格条显示的是**单本含税**与**总报价**（不含运费）；明细页最后一行是**单本到货价**（含运费）。如果你在手机上填了运费、电脑上没填，用「到货价」对比也会差一截。
